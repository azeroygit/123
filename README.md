# AdoptMe Trade Bot

AFK-бот для трейдов в **Adopt Me** (Roblox). Написан в том же стиле, что и твой
`AdoptMe Farm`: таблица настроек, `getgenv()`, тумблеры, `pcall`-запуск и лог
`start_error.txt`.

Что делает:

* сам принимает входящие запросы на трейд;
* читает **обе** стороны окна трейда (питомцы, пето-одежда, коляски, машины, еда, игрушки, яйца, гифты, стикеры, дома);
* считает стоимость каждого предмета по **[amvgg.com/values](https://amvgg.com/values)**;
* сам докидывает предметы со своей стороны из инвентаря, чтобы сделка оставалась в плюсе;
* принимает / отклоняет по порогу;
* кидает оффер в **Discord webhook** (кто что даёт, сколько это стоит, решение).

---

## 1. Установка

Нужен любой executor с `request` / `syn.request` (для вебхука и обновления цен),
`getconnections` или `firesignal` (для нажатий по кнопкам игры) и `writefile`
(для сохранения настроек).

```lua
loadstring(game:HttpGet("https://raw.githubusercontent.com/azeroygit/s/main/AdoptMeTradeBot.lua"))()
```

или открой `loader.lua`, впиши свой URL и запусти его.

При первом запуске создаётся папка `AdoptMeTradeBot/`:

```
AdoptMeTradeBot/
├── settings.json     # все настройки, сохраняются сами
├── values.lua        # кэш цен после "Update values"
├── log.txt           # последние 60 строк лога
├── gui_dump.txt      # дерево GUI (после "Dump GUI tree to file")
├── phone_dump.txt    # отчёт по окну Trade Phone (после "Scan trade phone")
└── start_error.txt   # ошибка запуска, если что-то упало
```

Окно бота: справа сверху, таскается за шапку.
`RightControl` — вкл/выкл (настраивается), `×` — скрыть, `–` — свернуть.
После `×` окно возвращается той же горячей клавишей.

## 2. Discord webhook

1. В Discord: **Настройки канала → Интеграции → Вебхуки → Новый вебхук → Копировать URL**.
2. В боте вставь URL в поле **Webhook URL**.
3. Нажми **Test webhook** — в канал придёт тестовое сообщение.

Что приходит на каждый оффер:

* **You receive** — что даёт тебе собеседник, с ценой каждого предмета;
* **You give** — что отдаёшь ты;
* **Value** — `их сумма ← | → твоя сумма (x-коэффициент)`;
* **Unpriced items** — если в окне есть предмет, которого нет в таблице цен;
* заголовок меняется на `Trade accepted` / `Trade declined`.

`Mention user id` — если вписать ID, бот будет тегать тебя в сообщении.
Спам по одному офферу не идёт: сообщение отправляется только когда меняется
**чужая** сторона трейда.

## 2b. Кирия — живая подпись в сообщениях

В бота встроена поддержка модуля **Kiria** (`Kiria.lua`): это не бот, а «персона» —
она берёт события трейда и превращает их в человеческие фразы + гифку + настроение,
и копит себе ранг/XP.

Что даёт:

* в карточке принятого трейда появляется её текст («We traded Owl for Shadow Dragon,
  that's +35% for us») и гифка, а имя вебхука становится `Kiria | Kirito's Lost Fragment`;
* при запуске она пишет приветствие (утро/день/вечер, сессия №, обещание про `MinAcceptRatio`);
* каждые 10 принятых сделок — карточка прогресса (`We're up 12% since we started`);
* каждые 30 минут тишины — карточка «всё ещё работаю» с теми же реальными цифрами;
* если в цикле бота случилась ошибка — раз в 15 минут приходит её «мне нужна помощь»;
* прогресс (ранг, число сделок) она хранит сама в `TradeBot/Kiria_memory.json`.

Счётчик сессии копится в боте: **net** (получено минус отдано), **%** от отданной
стоимости, сколько отдано/получено. Он виден в карточке принятого трейда (поле
`Session`) и в блоке Status. Всё считается только по реально принятым сделкам —
никаких выдуманных «теперь твои петы стоят N».

Управление: блок **Discord** → `Kiria persona in messages` (вкл/выкл) и
`Kiria module URL` (по умолчанию официальный репозиторий автора), плюс кнопка
**Test Kiria card** в блоке Tools — пришлёт пример карточки в канал.

Если модуль не скачался или executor не умеет `loadstring` — бот просто пишет
обычные карточки, в логе будет строка `kiria: ...`.

Кнопка **Session progress card** в Tools — прислать карточку прогресса вручную.

## 2c. Чего у нас нет (сравнение с платным ботом с ютуба)

У KiritoKun в шоукейсах есть фичи, которых у нас долго не было. Где смог — сделал,
где нужен реальный UI — честно помечено «бета» и ждёт дампа:

| Их фича | У нас | Почему |
|---|---|---|
| Trade Phone (создание листингов прямо из окна) | бета | `PhoneEnabled` + `Dry run`; окно читается, выставление листинга ждёт `phone_dump.txt` с экрана Робо Тодда |
| ask-листинги («даю X, хочу Y») и их авто-трейд | бета | наценка `Ask price: % above value`; сам трейд по ask-листингу делает игра |
| своп офферов, когда лимит | есть | `Max waiting offers` + `Drop the weakest offer` |
| авто-запросы трейда по списку ников | есть (`AutoRequestTrades`), но по UI-эвристике |
| фильтр плохих офферов | есть | `MinAcceptRatio` / `MaxAcceptRatio` / `RequireKnownValue` |
| вебхук-логи + профит | есть | карточки + `Session` + карточки прогресса |

Если хочешь листинги — открой экран листингов в игре, нажми **Dump GUI tree to
file**, скинь `AdoptMeTradeBot/gui_dump.txt`, и я по нему напишу модуль под
настоящие кнопки, а не наугад.

## 3. Как бот принимает решение

Для каждой стороны считается сумма:

```
value = базовая_цена_amvgg × fly × ride × neon × mega
```

Множители по умолчанию: Fly 1.03, Ride 1.05, Neon 2.20, Mega 5.00
(меняются в блоке **Your side**).

Дальше:

| Условие | Действие |
|---|---|
| твоя сторона пустая | бот сам докидывает предметы, пока не наберёт `их_цена / MinAcceptRatio` |
| `их_цена / твоя_цена >= MinAcceptRatio` | **Accept** |
| `их_цена / твоя_цена > MaxAcceptRatio` | **Decline** (защита от «слишком хорошо, чтобы быть правдой»; `0` = выключить) |
| есть предмет без цены и включён `RequireKnownValue` | **Decline** |
| `MinOfferValue` не набран | игнор |

**Fill mode**

* `profit` (по умолчанию) — докидывает максимум, при котором сделка ещё остаётся
  выгодной (ровно на границе `MinAcceptRatio`);
* `fair` — докидывает примерно на равную сумму;
* `manual` — ничего не трогает, только читает и принимает.

**Max items to give** — сколько слотов максимум занимать.
**Never give your only copy** — не отдавать единственный экземпляр питомца.

## 3b. Trade Phone / Trading Hub (бета)

В Adopt Me есть **Trading Phone** (игрушка в рюкзаке): она открывает окно
`Listings / Offers / History`. Листинги создаются только в **Trading Hub**, у
Робо Тодда, стоят **100 bucks** за штуку, максимум **2 активных**; выставленные
петы блокируются в инвентаре, пока листинг не снят.

Бот умеет работать с этим окном:

* открыть телефон (ищет кнопку/игрушку со словом `phone`);
* читать карточки офферов на твои листинги и считать их стоимость по amvgg;
* принимать оффер, если он не ниже порога, и отклонять слабые;
* сбрасывать самый слабый оффер, если их больше `Max waiting offers`;
* снимать листинг, который висит дольше `Take a listing down after N min`;
* пытаться выставить новый листинг с наценкой `Ask price: % above value`.

**Сначала включи `Dry run`** (он включён по умолчанию). В логе будет видно, что бот
нашёл и что он *собирался* нажать — ничего не нажимая:

```
phone (dry): would click "Accept" for accept an offer worth 1.240
phone: no create/post button here (posting works only in the Trading Hub)
```

Когда строки выглядят правильно — выключай `Dry run`.

Порог для офферов берётся из:
1. `Value of a listing I posted by hand` — впиши стоимость своего листинга
   (например `1.76` для Frost Dragon), бот умножит её на `MinAcceptRatio`;
2. либо из листингов, которые он выставил сам;
3. либо `Or accept offers worth at least` — жёсткий минимум в единицах amvgg.

Ничего из этого не задано — бот офферы не принимает (и пишет об этом в лог).

**Кнопки в Tools**

* `Scan trade phone` — отчёт по открытому окну (кнопки, карточки, суммы) в лог и
  в `AdoptMeTradeBot/phone_dump.txt`;
* `Open trade phone` — нажать игрушку за тебя.

Если авто-выставление листинга не идёт дальше выбора предмета — пришли
`phone_dump.txt` с экрана Робо Тодда: шаги «что хочу взамен» и «опубликовать»
я допишу под настоящие кнопки.

## 4. Списки (по одному имени в строке)

* **Trade request targets** — ники, кому бот сам будет кидать запрос (только если включён `Send trade requests to targets`).
* **Allowed to give** — белый список предметов, которые можно отдавать. Пусто = всё, кроме `Never give`.
* **Never give** — чёрный список.
* **Wanted items** — что хочешь получать (работает с `Only accept wanted items`).
* **Aliases** — если игра показывает предмет не так, как он называется на amvgg:

  ```
  Black Chested Pheasant = Black-Chested Pheasant
  ```

## 5. Цены

В скрипт вшита таблица на момент генерации (**1756 предметов**, 10 категорий),
так что бот работает сразу, без интернета.

Обновить:

* **в игре** — кнопка `Update values from amvgg.com` (тянет все 10 страниц,
  пишет кэш в `values.lua`, при следующем запуске берётся он);
* **на ПК** — `tools/update-values.ps1`, он заново скрапит сайт, обновляет
  `values/values.lua`, `values/pets.json` и переписывает вшитый блок в
  `AdoptMeTradeBot.lua` между маркерами `VALUES_BEGIN` / `VALUES_END`:

  ```powershell
  powershell -ExecutionPolicy Bypass -File tools\update-values.ps1
  ```

## 6. Первый запуск: что проверить

Интерфейс игры я не могу протестировать за тебя, поэтому в боте есть два
диагностических инструмента:

1. **Scan trade window** — пишет в лог, нашёл ли он окно, сколько предметов
   распознал и на какую сумму. Если после открытого трейда пишет
   `no trade / request window found` — значит структура окна другая.
2. **Dump GUI tree to file** — сохраняет всё дерево `PlayerGui` в
   `AdoptMeTradeBot/gui_dump.txt`. По нему видно, как называются окна, кнопки и
   слоты, и можно поправить эвристики.

Если бот путает стороны (твоё считает чужим) — выключи
**Your offer is on the left** в блоке Advanced.

Если предметы не докидываются — почти всегда виновата виртуализированная сетка
инвентаря: бот сам листает её (`searching inventory`), но если слоты не кнопки,
поможет `Dump GUI tree` и правка `clickInventoryItem` / `findSlot`.

## 7. Ограничения

* Adopt Me — это Roblox, автоматизация нарушает их правила. Аккаунт могут
  ограничить, это твой риск.
* Скрипт работает через игровой UI (кнопки/слоты), а не через скрытые ручки:
  он не «взламывает» трейд, а нажимает за тебя. Поэтому после обновления игры
  селекторы могут поехать — отсюда `Scan` / `Dump`.
* `Use remote fallback` дёргает найденные remote-события для исходящих
  запросов. По умолчанию выключено: чужие ремоуты с неверными аргументами
  могут кикнуть с сервера.
* Цены amvgg — это их внутренняя шкала (Bat Dragon = 5.53), а не робуксы.
  Сравнивать имеет смысл только внутри одной категории.
* Бот не «фармит» предметы и не обходит античит — только трейд-логика.
